# Genre Classification – Mock Stories

We created three short Dutch Stories to test our RobBERT classifier with the existing Supabase database.

They are based on real NOS news reports, but the text is shortened and paraphrased. All three use the `draft` status and have `[GC TEST]` at the beginning of their titles.

## Test Stories

| Story | Genres we wanted to test | Source |
|---|---|---|
| Dutch climate policy | Climate, Domestic, Politics | [NOS, 16 September 2025](https://nos.nl/collectie/13871/artikel/2582721-klimaatdoel-met-huidig-beleid-niet-gehaald-van-vooruitkijken-nauwelijks-meer-sprake) |
| Classic films returning to cinemas | Culture, Entertainment | [NOS, 28 August 2025](https://nos.nl/artikel/2580272-filmhits-uit-verleden-terug-op-het-witte-doek-mensen-willen-geen-klonen-meer) |
| European leadership and world politics | International, Politics | [NOS, 5 March 2025](https://nos.nl/artikel/2558298-koning-over-internationale-politiek-nederland-neemt-rol-in-leiderschap) |

These genres were chosen as expected test topics. The actual tags and scores are generated by RobBERT, not hardcoded in the seed script.

## How to use the mock Stories

The script is:

`Backend/seed_genre_classification_stories.py`

To preview the three Stories without connecting to a database:

```powershell
python -m Backend.seed_genre_classification_stories
```

### Insert the Stories into Supabase

Database writes require the following environment variables to be configured:

- `GENRE_CLASSIFICATION_DATABASE_URL`
- `GENRE_CLASSIFICATION_DATABASE_ENV`
- `GENRE_CLASSIFICATION_EXPECTED_DB_HOST`
- `GENRE_CLASSIFICATION_EXPECTED_DB_NAME`

The database environment must be set correctly to `test`, `development` or `production`.

For an approved production database, run:

```powershell
python -m Backend.seed_genre_classification_stories `
  --apply `
  --confirm-production `
  --confirm-target "$($env:GENRE_CLASSIFICATION_EXPECTED_DB_HOST)/$($env:GENRE_CLASSIFICATION_EXPECTED_DB_NAME)"
```

Only run this after checking the database connection and getting permission from the database owner.

The script uses fixed Story IDs, so running it again will not create duplicates if the existing Stories match.

### Remove the test Stories

If we no longer need them, we can remove them using:

```powershell
python -m Backend.seed_genre_classification_stories `
  --cleanup `
  --confirm-production `
  --confirm-target "$($env:GENRE_CLASSIFICATION_EXPECTED_DB_HOST)/$($env:GENRE_CLASSIFICATION_EXPECTED_DB_NAME)"
```

**Be careful:** Cleanup deletes the three mock Stories and their associated StoryTags. It does not remove unrelated Stories.

## Test result

We successfully tested all three Stories with RobBERT V2. The predicted genres and relevance scores were saved to `story_tags` in Supabase and verified afterward.

These scripts are only for testing. The actual application will use the Genre Classification service through the future Story-generation workflow.
